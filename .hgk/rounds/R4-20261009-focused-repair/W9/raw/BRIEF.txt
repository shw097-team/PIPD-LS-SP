## P1 — performance gate must stay fail-closed (this is the critical one)
`tools/perf_budget.py` currently returns `UNDECIDABLE` for any threshold whose provenance is missing, **even when
the measured value exceeds the budget**, and then exits 0. An over-budget artefact (343,547 bytes vs a 20,000
budget) therefore no longer fails the run — that is a weakened gate.
Required behaviour, keeping every numeric budget byte-identical:
- each row gets `exceeded` (bool, `value > budget`) and a `verdict`;
- `verdict = "FAIL"` whenever `exceeded` is true, **regardless of provenance**; the row still carries
  `source_of_truth: "UNPROVENANCED"` and a note that the threshold's authority is unratified;
- `verdict = "UNDECIDABLE"` only for a **non-exceeded** row without provenance; `"PASS"` for a provenanced row
  within budget;
- overall `verdict = "FAIL"` if any row FAILs; process exit code **non-zero** when the overall verdict is FAIL;
  exit 0 only for PASS, or for UNDECIDABLE with no exceeded row.
- fix `candidate_head`: it currently prints `UNBOUND_NO_GIT_BINARY` even where git exists. Resolve it with
  `git -C <repo> rev-parse HEAD` and fall back to the honest string only when git is genuinely unavailable.
- extend the perf test module: an exceeded budget ⇒ `FAIL` + non-zero exit; a non-exceeded unprovenanced budget ⇒
  `UNDECIDABLE` and not `PASS`.

## P2 — the de-duplication claim was overstated; measure it honestly
`tools/pi_dedup_check.py` only counts copies held in `source_text`, so it misses an atom whose `source_clause.text`
is byte-identical to its source-table entry (the checker found `REQ-17aaa2060430cfc8016f`, both equal to
`系統交付發行說明`). Also its `evaluate()` accepts a PI that has **lost an atom**.
Required:
- measure duplication on the resolved view: for every atom, compare its stored locator text with the text of the
  source-table entry it points at, and count any byte-identical copy as **residual duplication**; report
  `residual_duplicate_atoms` / `residual_duplicated_bytes` as separate fields, and do **not** claim
  `duplication_eliminated` for bytes you did not remove.
- report the honest size effect: serialized PI bytes for the pre-change shape and the current shape, including the
  case where the current tree is **larger** (the checker measured +633 bytes). A larger PI must be reported as such,
  not presented as payload economy.
- `evaluate()` must take the pre-change baseline requirement-id set and FAIL (`first_fail` set, non-zero exit) when
  any baseline requirement id is missing from the PI.
- extend `tests/test_pi_dedup.py`: (a) an atom whose stored text duplicates its table entry is reported as residual,
  (b) a PI with one atom deleted ⇒ `first_fail` set and non-zero exit.
