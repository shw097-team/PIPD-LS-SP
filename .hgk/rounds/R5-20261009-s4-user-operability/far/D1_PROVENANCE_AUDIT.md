## Confirmed instance - `tools/perf_budget.py` (`historical` block) - severity HIGH

**Where.** The block is built at **lines 244-251** as a comprehension over the advisory rows taking
`r["value"]`, and every advisory row's value comes from a live measurement earlier in `main()`:

- `context_bytes_per_artefact` <- `worst = max(sizes.values())` (**lines 200-203**)
- `compile_chain_ms` <- `perf_counter` delta (**lines 176-182**)
- `validate_19_contracts_ms` <- `perf_counter` delta (**lines 185-193**)
- `cli_cold_start_ms` <- `perf_counter` delta (**lines 194-199**)

**The claim it makes.** The block's own note (**lines 245-246**) says *"the recorded verdicts are
preserved verbatim and must never be rewritten"*; the module comment (**lines 32-33**) says *"The
historical 343,547 > 20,000 FAIL is preserved verbatim and is still emitted."* The owner ruling
`docs/OWNER_ADJUDICATION_R5_S4_2026-10-10.json#/S2_HISTORICAL_FAIL = PRESERVE` asserts the same, and
its disclosure list claims *"the historical FAIL was not rewritten."*

**Why it is false.** Nothing in the block reads the stored value back.
**READ-OR-COMPUTE: COMPUTE** - the value is taken from the live row object, never loaded from
`.hgk/artifacts/s2/PERF_BUDGET.json` (whose `historical.rows[].value` records the frozen numbers) nor
from `.hgk/artifacts/s2/BYTES_PER_ATOM_BASELINE.json` (`pi_bytes = 343547`).

### Measured
| field | committed artifact | live `--check` |
|---|---|---|
| `context_bytes_per_artefact` | 343547 | 343547 (4/4 runs, deterministic here) |
| `compile_chain_ms` | 818.2 | 805.4 / 744.1 / 707.4 |
| `validate_19_contracts_ms` | 2.0 | 2.0 / 2.1 / 2.0 |
| `cli_cold_start_ms` | 110.4 | 126.0 / 109.0 / 123.7 |

**Honest reading.** On this checkout the *bytes* row is deterministic and coincidentally equals the
recorded 343547 (artefact size is a function of the source spec, and the committed artifact was
regenerated 2026-10-10 13:43). The brief's claim that two runs printed **366299 / 365351 did not
reproduce** - 4 runs printed 343547 each. The rows that **demonstrably drift** are the three timing
rows, which differ from the committed `historical` record on every run.

### Blast radius

  `preserved_fails` (line 108); it never reads the committed value nor pins the emitted number.
- `docs/OWNER_ADJUDICATION_R5_S4_2026-10-10.json` - ruling `S2_HISTORICAL_FAIL: PRESERVE` and the
