## Why that is the same class

`src/pipd_ls_sp/workspace.py`, `init_workspace(root)`, creates the skeleton directories
(`docs`, `schemas`, `src`, `tests`, `dist`) and then calls
`registry.load_registry(root / "schemas")` — passing the `<root>/schemas` directory it has JUST
created, which is empty. So `init` can never succeed on a fresh or installed root. The stated job
of the function is "create the skeleton and report how many contract families exist"; it must
therefore read the registry from wherever the registry actually is, exactly as `doctor` and
`validate` now do.

## What to change

1. `workspace.init_workspace` must resolve the schemas surface through the SAME resolver the rest
   of the CLI now uses — do not hand-roll a second lookup, and do not read
   `<root>/schemas` unconditionally. `registry.load_registry()` with no argument already resolves
   through the shared chain; use the shared resolution path and keep one order of preference.
2. Report which surface produced the family list, in the same `{mode, path, tried}` shape the
   other commands use, so an operator can see it. Do not remove or rename any field that is
   already in the returned dict (`verdict`, `root`, `created`, `contract_families` must survive).
3. If no surface resolves, fail closed with a typed code and a message that names what was tried —

4. A workspace-local `<root>/schemas` that genuinely carries a `registry.json` must still win, so
   an initialised workspace keeps reading its own copy. Do not break that.
