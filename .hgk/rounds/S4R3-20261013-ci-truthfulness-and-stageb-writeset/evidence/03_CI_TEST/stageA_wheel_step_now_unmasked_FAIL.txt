# Stage A hosted `ci` run 38352344981 (job 115147347183), head ee6e3b0

The first repair pass guarded the unittest pipelines but not the wheel step. Independent
verification found that residual; adding `set -euo pipefail` to that step turned it RED on the
first run - which is the whole point. What the green badge had been hiding:

  pipd doctor  (from a scratch cwd, against the freshly built and installed wheel)
    "verdict": "FAIL"
    "findings": ["resolved schemas surface (mode=NONE): no schemas dir containing registry.json
                  was found; tried: <wheelvenv>/lib/python3.11/schemas"]

The wheel's own RECORD (see the `adding ...` lines) ships only pipd_ls_sp/*.py plus metadata -
no schemas payload. So an installed wheel cannot resolve its schemas surface and `pipd doctor`
exits 1. In the source check-out the same command PASSES (tests/test_wheel_distribution.py
'run from a scratch cwd must PASS and name the INSTALLED surface ... ok'), because the repo's
own schemas/ directory is found instead. Same command, different subject: the defect lives in
the distribution, not in the workspace.

This is NOT repaired in this round and is not hidden by relaxing `doctor`: read the log below.
